# Changelog versions follow semver

Each release in a changelog bumps its version as Semantic Versioning requires for the changes it lists, compared with the release just below it: a breaking change needs a new major version, and a new feature needs at least a new minor version.

Applies to every `CHANGELOG.md` in the repository, written in the Keep a Changelog style.

Exceptions: the Unreleased section, which has no version yet, and a changelog with a single release, which has nothing to compare with.
